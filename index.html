발표 · 시연 영상

썸네일을 누르면 그 자리에서 바로 재생됩니다. 챕터 카드는 10분 본편의 해당 구간만 재생하고, 시연은 실제 운영 서비스(movpick.onrender.com)에서 일반 회원과 테스트 관리자 계정을 비교합니다.

기획 의도

명당 자리는 '새로고침'으로 잡는다?

  • 명당 자리는 대부분 매진 뒤 취소표로 나오지만, 언제 나올지 알 수 없습니다.
  • 상영 정보는 체인마다 다른 앱에 흩어져 있어 같은 영화를 세 번 검색해야 합니다.
  • 목록은 잔여석 숫자만 보여 줘서, 그 자리가 명당인지는 예매 단계에서야 압니다.

→ 수집은 RPA가, 감시는 서버가 하고, 사용자는 "명당 자리가 비었다"는 알림만 받도록 설계했습니다.

핵심 기능

수집 → 판단 → 알림, 하나의 파이프라인

  • RPA 자동 동기화 — 30분 주기, 오늘·내일, 체인별 어댑터 · HTTP 우선 → Playwright 폴백
  • 명당 점수 모델 — 스크린 기준 약 2/3 지점·중앙 열 거리 함수(NumPy), 상위 18% 하이라이트 · 히트맵
  • 실시간 취소표 알림 — 새로 빈 좌석만 diff 감지 → 사용자별 WebSocket 팝업 · 웹훅(텔레그램·디스코드·이메일)
  • 권한 분리 — 일반 회원 / 읽기 전용 테스트 관리자 / .env 실제 관리자, 서버가 403으로 강제

01

실제 3사 데이터

메가박스·롯데시네마는 서버가 직접, CGV는 국외 IP 차단 때문에 국내 원격 수집기가 토큰 인증 API로 보냅니다. 하루 약 450회차를 동기화합니다.

02

정직한 한계 표기

영화관은 잔여석 '수'만 공개하므로 좌석 배치는 추정값이며, 화면과 영상에서 그렇게 밝힙니다. 실데이터가 있으면 모의 데이터와 섞지 않습니다.

03

검증 가능한 운영

/health가 배포 커밋 해시를 돌려주고, CI가 테스트 · 프런트 빌드 · Docker 이미지 기동을 확인한 뒤 배포합니다.
